# 社区生态运营实操指南

核心：围绕一项值得长期投入的共同事业，让人持续受益、彼此创造价值，并不断产生新的建设者。

运营的主线是：**共同需要 → 一起行动 → 获得真实成果 → 积累信任与能力 → 更多人参与和承担。**

本指南供社区发起人和日常运营者使用，从一小群人的合作起步，逐步形成能够接续、协作和生长的生态。文中的人数、周期和安排是试运营参考，推进以实际成果和承接能力为准。用于生道与生制时，按第 11 节落实对应要求。

## 1 起步目标：把共同事业落到一件能做成的事上

先明确谁需要什么，以及大家可以一起做成什么。首阶段集中解决一个共同需要，让参与者得到真实成果。

### 1.1 起步说明：用一页纸讲清参与的理由

发起人先填下面六项，再拿着它与目标人群交谈。交谈后改写，不急着把第一版做成宣传口号。

| 项目     | 要写清什么                                           |
| -------- | ---------------------------------------------------- |
| 服务谁   | 一类具体的人，以及他们当前所处的情境                 |
| 共同需要 | 最近反复遇到、值得一起解决的问题                     |
| 长期方向 | 这个问题持续解决以后，大家希望形成什么能力和生活条件 |
| 首次行动 | 第一批人一起完成什么，结果由谁、按什么标准确认       |
| 参与成本 | 所需时间、费用、准备和责任                           |
| 已有条件 | 现有人员、经验、工具、场地、资金及可用机会           |

同时问清三个问题：哪些价值需要成员彼此协作才能获得；已有渠道在哪一步无法充分满足；什么需要会再次出现，让大家值得持续联系。交谈中核对各方能提供的帮助，确保需要与能力能够互补。

起步表述模板：

> 我们聚集【具体人群】，一起解决【具体问题】。第一轮用【时间】完成【成果】，由【使用者或受益者】按【标准】确认。参与需要【投入】，目前已有【条件】。长期希望积累【能力、关系与可接续的成果】。

例如：聚集有基础作品、想提高交付能力的独立内容创作者，围绕一个已经确认的真实需求，共同完成一份可使用的内容成果；留下需求判断、分工、修改和验收的方法。后续再判断能否持续承接需求、培养新人。

这个例子是行动设计示例，实际启动前须确认需求、参与者与可用条件。

### 1.2 需求交谈：用过去的行为判断需要是否真实

首周可先与 5—10 位目标人群交谈，每次约 20 分钟，记录事实和具体例子。

- 最近一次遇到这个问题是什么时候？当时怎样解决？
- 已经投入过多少时间、精力或费用？最难的一步是什么？
- 哪部分需要别人的经验、协作或支持？
- 如果一起做，你能提供什么、需要什么、能投入多少时间？
- 第一轮出现什么结果，你才会觉得值得继续？

交谈后，选出一个重复出现、当前可解决、能够共同参与的需要。若只有口头赞同，尚无人愿意安排时间或提供真实需求，继续缩小人群和问题。

## 2 首七天：找到首批伙伴并约定第一次行动

首周的完成标准是：有人愿意参与，行动有真实需要，分工与成果要求已经明确。

| 时间      | 发起人做什么                             | 当天留下什么                 |
| --------- | ---------------------------------------- | ---------------------------- |
| 第 1 天   | 填起步说明，列出可以交谈的人             | 一页起步说明、联系名单       |
| 第 2—3 天 | 完成需求交谈，归纳重复问题和可用条件     | 需求记录、首轮问题           |
| 第 4 天   | 设计第一次行动，核对时间、费用和成果要求 | 一张行动卡                   |
| 第 5 天   | 邀请合适的人，逐一确认投入和需要         | 首批参与名单、每人的承诺     |
| 第 6 天   | 完成准备、配对和必要材料交接             | 分工、资料入口、反馈方式     |
| 第 7 天   | 启动第一次行动，确认首次检查时间         | 开始执行的任务、下次检查安排 |

### 2.1 首批邀请：把现有条件和参与要求说具体

首批可从 3—8 人的小范围尝试，人数以能得到实际回应和指导为限。优先邀请有共同需要、愿意投入、能遵守约定的人；能力互补比履历相似更有用。

名单可以从过去合作过的人、相关社群中正在讨论具体问题的人、同行引荐三处建立。完全没有熟人时，先在目标人群已有的交流场合了解需要，提供一份自己能做出的具体帮助，再邀请愿意进一步交流的人。

发起人准备一个能说明自己当前能力的例子，以及第一轮能够实际提供的支持。邀请时说明为什么想到对方，把已有成果、时间安排和投入要求放在同一份说明里。

邀请模板：

> 我正在组织一次【行动】，帮助【人群】解决【问题】。我们计划在【时间】一起完成【成果】，目前已有【条件】。你可以承担【具体部分】，预计需要【投入】，能得到【当前确实可提供的支持】。这次结束后一起复盘，再决定是否继续。

愿意了解的人可以先看说明；愿意行动的人再确认任务。涉及收费、报酬或资源使用，开始前讲清具体安排。

### 2.2 第一次行动：让每个人都有可完成的部分

第一次行动应当满足以下条件：

- 有明确的使用者或受益者，结果能被确认。
- 需要成员之间发生实际协作，大家知道彼此提供了什么。
- 任务难度与当前能力相配，能较快获得反馈。
- 成果、经验和协作记录能够成为下一轮的基础。

行动可以是完成一个项目、解决一次求助、共同改进一项作品，或组织一次有明确受益人的互助。长周期项目先选一个可独立验收的阶段成果。

先选一种能够重复发生的小互助：一人提出具体问题，另一人提供经验或协作，受益者确认得到什么帮助，再约定需要的后续行动。专业问题、学习难点、生活互助和共同体验，都可以按这个办法起步。

### 2.3 一轮示例：三个人共同改进一份活动说明

以下为演示情境：某活动组织者提出，其报名说明让读者难以理解时间、地点、费用和参与要求，希望得到改进。

| 项目       | 具体安排                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| 共同需要   | 组织者需要清晰的说明，参与者希望练习需求判断、写作与协作                 |
| 本轮成果   | 一份经组织者核对并接受的活动说明，以及一份检查清单                       |
| 三人分工   | 一人核对事实与需求，一人写初稿，一人从读者角度检查；共同修改             |
| 一周安排   | 第一天确认需要和约定，第三天交初稿，第五天检查修改，第七天确认与复盘     |
| 确认标准   | 活动事实准确，读者能找到时间、地点、费用、参与条件和报名方式             |
| 开始前讲清 | 可投入时间、报酬安排、材料与成果使用范围，由有关各方确认                 |
| 留下积累   | 需求表、说明模板、检查清单，以及三人的具体贡献                           |
| 下一轮     | 愿意继续的人选择新的真实需要，由本轮一位参与者承担协调，原负责人提供支持 |

其他主题也可以这样设计：围绕实际需要，把共同参与、成果确认、经验积累和责任交接放进同一轮行动。

## 3 前九十天：先重复做成，再培养接续者

每个阶段都有行动、成果和推进条件。到期先判断结果，再决定继续、调整或扩大。

| 阶段        | 重点行动                                         | 应当留下的成果                           | 进入下一阶段的条件                                   |
| ----------- | ------------------------------------------------ | ---------------------------------------- | ---------------------------------------------------- |
| 第 1—7 天   | 确认需要、伙伴与第一次行动                       | 起步说明、行动卡、实际承诺               | 需求真实，有人能开始执行                             |
| 第 8—30 天  | 完成首轮，复盘后再做一轮                         | 使用者确认的成果、贡献记录、改进后的做法 | 有人实际受益并愿意再次投入；第二轮能利用第一轮的积累 |
| 第 31—60 天 | 稳定重复，把部分组织工作交给合适的人             | 固定节奏、可复用材料、交接记录           | 有人能在明确范围内带完一轮；成员之间能直接协作       |
| 第 61—90 天 | 小批接入新人，验证接续能力；有互补团队时尝试合作 | 新人首次成果、接续者带队记录、协作复盘   | 新人得到支持，原有成果质量保持，时间和资金能够承接   |

阶段复盘只做一个主要判断：**保持、改进、缩小、扩大或结束这项行动。** 写明理由、负责人和下次检查时间。

需要尚未确认，继续交谈；成果质量不足，先改任务；接续能力不足，先带人；资源不足，先缩小承诺。某项行动结束后，保留可用成果、经验和合作关系，按已明确的权利与约定处理。

## 4 每周运转：让需要、任务、成果和反馈连起来

建立一个大家记得住的固定节奏，让执行占据主要时间，让交流能够推动下一步。

### 4.1 每周安排：一次推进、一次确认、一次复盘

以下是一周行动的参考安排，按实际工作周期调整。

| 环节     | 怎么做                                       | 完成标志                       |
| -------- | -------------------------------------------- | ------------------------------ |
| 周初确认 | 汇总需要，选出本周最值得做的事，核对承接能力 | 每项任务有人、期限和成果标准   |
| 周中推进 | 执行、配对协作、处理阻碍；出现变化及时同步   | 协作者知道当前状态和所需帮助   |
| 周末确认 | 由使用者或约定的确认人检查成果               | 结果被接受，或明确需要怎样改进 |
| 周末复盘 | 记录做成什么、谁作出贡献、下轮改什么         | 更新记录和材料，排出下一步     |

首次碰头可控制在 45—60 分钟：明确共同需要，核对任务与分工，安排协作，约定下一次反馈。后续可以用简短书面同步完成的事情，直接书面处理。

### 4.2 状态同步：让协作者及时知道变化

开始前写清任务；执行中及时报告影响别人安排的变化；完成后交付成果和必要说明。

状态模板：

> 已完成【什么】；当前在做【什么】；遇到【阻碍】；需要【谁提供什么】；预计【何时交付】。如果原承诺需要调整，建议【新安排】。

响应时间根据任务的紧急程度和大家的可用时间约定。每个人能清楚表达“能做”“不能做”“需要更多信息”或“何时答复”。

### 4.3 基础入口：让新人和协作者找得到东西

起步只需一个沟通入口和一个稳定的资料入口，放好以下内容：

- 起步说明和当前参与安排。
- 正在进行的任务、负责人、期限和状态。
- 已完成的成果、使用说明和允许的使用范围。
- 已确认的贡献与复盘记录。
- 谁负责接待、协调、确认成果和处理问题。

工具以现有成员能方便使用为准。先解决信息找不到、任务交接不清的问题，再增加功能。

### 4.4 需求匹配：让互助从提出需要走到确认结果

每周固定征集一次“我需要什么、我能提供什么、何时有空”，把当前需要与可用帮助放在一起核对。

1. 求助者说明问题、已经试过的办法、希望得到的结果与期限。
2. 愿意帮助的人说明经验、可提供的具体支持和可用时间。
3. 介绍前取得双方同意，再交接必要的信息。
4. 双方约定下一步，由成员直接推进，运营者处理需要其协调的阻碍。
5. 在约定时间确认结果：已帮助、仍在推进或未匹配成功；记录需要怎样继续。

首次活动形成的约定，可在两天内做一次简短跟进，确认是否开始执行；结果按任务期限检查。成功互助后再问下一项需要，逐步促成第二次、第三次合作。

每周复盘未匹配的需要，分清缺的是相应能力、可用时间、任务说明还是信任。求助增长快于支持能力时，调整接入范围、寻找互补伙伴或整理可复用的解答。

## 5 参与与带教：让新人完成第一件事，让有能力的人逐步承担

按意愿、能力和可用时间安排参与，让人有机会从获得帮助走向提供帮助和组织行动。

### 5.1 新人接入：尽快获得第一次真实收获

每位开始参与的新人，有一个明确联系人和一次适合自己的互助或行动机会。

1. 了解：读起步说明，讲清自己的需要、经验和可用时间。
2. 选择：与联系人确定互助或实做任务，明确合作伙伴、反馈时间和结果确认方式。
3. 行动：参加互助或完成自己的任务，获得具体回应和指导。
4. 确认：说明得到什么帮助或成果怎样被使用，核对实际贡献。
5. 接续：选择下一件事，或者明确暂停、调整参与方式。

可以把“参与后的第一周获得一次可确认的收获”作为起步目标。任务周期较长时，先安排有实际价值的小成果。

首次收获可以是问题得到回应、找到合适伙伴或获得能用上的方法。按实际需要邀请自愿提供帮助的人，安排双方同意的协作。对暂时只想了解的人，提供资料和可选择的参与机会，了解其实际收获。

### 5.2 参与深度：让承诺与责任相配

不同的人可以投入不同深度。少量参与的人承担小任务，持续参与的人承担稳定分工，能够组织事情的人逐步承担协调与带教。

开始前问清：愿意承担什么、每周可用多少时间、需要什么帮助。以实际承诺检查履行情况。获得求助的人，也可以通过整理经验、反馈结果、帮助后来者等方式贡献。

只接受支持、帮助他人、组织行动，是可以按实际情况调整的参与方式；尊重个人意愿和已经接受的责任。持续贡献的人可以拒绝新的任务，新的工作须另行确认投入与支持。

需要稀缺资源或大量指导的活动，提前说明参与条件、支持范围和名额。出现长期超出承接能力的需求，及时调整。

### 5.3 接续培养：从带完一件小事开始

对持续可靠、愿意承担的人，逐步交接组织工作：

1. 跟着做一轮，理解需要、分工、成果标准和常见问题。
2. 负责一个完整的小任务，包括沟通、执行和确认。
3. 带一名新人完成任务，练习指导与反馈。
4. 在明确范围内组织一轮行动，原负责人提供约定的支持。
5. 复盘这轮行动，补齐材料和交接中的缺口。

是否可以扩大责任，看实际表现：能否判断需要、安排任务、及时同步、解决问题、确认成果、照顾协作关系。任务授权范围、资源额度和求助通道提前写清；涉及正式职务时，按所在组织的规则办理。

有意愿的人也可以主动提出行动，说明目标、参与者、成果、资源需要和自己愿意承担的部分。在相应权限内确认安排后，由提出者组织，其他人提供约定支持，结束后共同复盘。

### 5.4 接续验证：确认减少日常推动后仍能运转

已有合适的人承担任务后，预告一轮接续观察。日常行动可观察两周；周期较长的行动观察一个完整周期。

- 开始前交清负责人、任务、资料、权限与求助渠道，记录上一轮的成果和维护负担作为对照。
- 原负责人减少普通事项的逐项撮合和催办，继续履行既有责任、成果检查与必要支持。
- 观察需要是否有人回应、协作是否推进、成果是否被确认、新人是否得到照应，以及工作是否集中压到另一个人身上。
- 结束后记录哪些事情能接续，哪些仍需帮助，再修复具体缺口。

遇到超出接续者权限或能力的问题，及时提供支持。如果行动停止，先查需求是否仍在、责任是否交清、资源是否够用，再决定调整。能够接续的标志是工作和责任被可靠承接。

## 6 贡献与积累：让今天做的事成为下一次的基础

每轮都留下可使用的成果、可核对的贡献和可接续的经验，让参与者看到自己的努力怎样产生价值。

### 6.1 贡献记录：把事情和作用写清楚

记录具体贡献及其证据，包含完成任务、帮助他人、日常维护、培养新人和改进方法。记录由相关人核对，发现遗漏或错误及时修正。

| 项目         | 记录要求                               |
| ------------ | -------------------------------------- |
| 谁作出贡献   | 实际承担者及其具体部分                 |
| 做了什么     | 行动、困难、投入与交付物               |
| 产生什么作用 | 受益人反馈、被采用的成果或可核对的变化 |
| 谁能确认     | 共同参与者、使用者或约定的确认人       |
| 约定怎样回应 | 已明确的报酬、认可、后续支持或其他安排 |
| 留下什么     | 方法、材料、经验和交接对象             |

投入很大却未达成预期时，如实记录结果，同时记录有效尝试、承担的责任和可复用的经验。作用尚需观察的贡献，保留证据和后续检查时间。

### 6.2 成果复用：明确怎样使用和怎样改进

每个准备复用的成果，补齐五项：当前用途、适用条件、使用方法、已知问题、维护人。说明归属、查阅范围与允许的使用方式，需要授权时先获得授权。

一轮结束后，至少选出一件下一轮确实会用的积累，例如需求表、操作方法、案例、检查清单或带教材料。用过后再改进，逐渐形成共同方法。

### 6.3 贡献回应：及时兑现已经明确的安排

及时确认贡献，兑现约定，提供具体反馈。认可时说明“谁解决了什么、产生了什么作用”，让后来者理解这种贡献。

需要金钱报酬、长期权益或其他资源安排的事项，行动开始前讲清条件、承担方和处理方式。贡献记录是核对事实的材料，具体权利仍按相应规则和约定确认。用于生组时，按第 11 节区分产出分配与产权分配。

## 7 协作保障：把承诺、权限和问题处理提前讲清

用简明、可执行的安排保护参与者和合作，让问题出现时有明确的处理路径。

### 7.1 开始前约定：至少回答六件事

每项行动开始前，参与者能找到以下答案：

- 目标和范围是什么，哪些事情目前能够承担？
- 谁负责执行、谁确认成果、谁有权调整安排？
- 时间、资金、工具和材料由谁提供，使用范围是什么？
- 贡献怎样记录，约定的回报怎样兑现？
- 信息与成果向谁开放，公开传播需要怎样确认？
- 遇到异议、违约或退出，找谁处理，怎样交接？

已有组织规则覆盖的事项，直接说明所依据的规则；运营安排在相应权限内补充具体执行方式。

把行为约定写进同一页说明：尊重他人，避免骚扰、欺诈和反复干扰；转发个人信息或交流记录前取得许可；商业推广说明有关利益并使用约定的场合；写清问题反馈、处理和异议通道。明确谁在已有权限内采取提醒、限制有关活动或其他处置，规则一致执行。

### 7.2 问题处理：先确认事实，再决定下一步

出现延误、冲突或承诺未履行时，尽快处理对行动和协作者的影响。

1. 记录：发生了什么、原约定是什么、影响了谁。
2. 听取：相关人补充事实、证据和自己的需要。
3. 处置：按已有权限与规则决定补救、调整、交接或终止有关安排。
4. 反馈：把处理结果告知相关人，说明异议反馈路径和复查时间。

涉及当前处理人自身的问题，使用约定的其他反馈通道。对外讲述成果或案例前，确认真实性和当事人的信息使用安排。

### 7.3 参与退出：把正在承担的事情交接好

参与者需要减少投入或退出某项活动时，说明尚未完成的承诺、交付已有材料、安排必要交接，并按约定处理费用、资源和成果使用。

活动参与的调整与正式组织身份的变动分别办理。涉及生道与生制时，按正文区分各身份、财产与退出事项。

## 8 资源保障：让维护工作有承接能力

把日常维护的时间和费用计入运营成本，使已经承诺的支持能够持续兑现。

### 8.1 时间安排：先明确每周能承担多少

发起人和维护者列出每周可投入的时间，覆盖需求了解、接待、协调、带教、复盘和资料维护。保留处理突发问题的余量。

每周复盘时看：哪些工作只有一个人会做，哪些工作反复出现，哪些承诺已经超出可用时间。优先缩小行动范围、整理重复做法、完成交接，再决定增加参与者。

### 8.2 费用安排：写清支出上限与来源

启动前列出一个行动周期内的必要费用，包括工具、场地、材料和已明确的报酬。写清费用承担方、资金来源、支出上限、审批方式和记录人。

可按实际条件选择发起人投入、费用分担、收费服务或已确认的支持，说明各自提供的内容和要求。每轮结束后核对实际收支与未履行事项，启动下一轮前确认资金已经能够覆盖对应承诺。

### 8.3 暂停条件：及时收缩无法持续的承诺

如果维护者持续过载、成果质量连续下降、资金无法覆盖已计划支出，或同一问题反复伤害协作，暂停相应扩招或行动。明确要修复什么、由谁处理、何时复查，再决定恢复。

## 9 生态生长：让新行动能够借助已有积累

当基础合作稳定、有人能够接续时，逐步连接互补的人与团队，让人才、知识、机会和资源通过真实需要流动。

### 9.1 扩大条件：先核对承接能力

扩大前逐项检查：

- 已有行动能够重复产生被确认的成果。
- 参与者有再次投入的行为，成员之间发生直接协作。
- 有人能在明确范围内组织行动，并获得必要支持。
- 新人有联系人、适合的任务和反馈安排。
- 维护时间、资金和资料能覆盖新增需要。

小批加入新人，完整观察一轮。确认原有参与者和新人都能获得支持，再决定下一批。保持与外部使用者、同行和需求来源的联系，让成果接受外部反馈。

对外招募可以从一份真实成果开始：经允许展示解决了什么问题、参与者承担了什么、留下了什么，以及下一轮具体需要谁。把传播内容连接到清楚的参与说明，再逐一确认投入；参与名额以实际接待与带教能力为限。

### 9.2 团队协作：围绕一个匹配的需要先合作一次

一个团队出现超出自身能力的需要时，找具备互补经验的团队，共同完成一项范围明确的协作。

流程：**提出需要 → 核对能力与条件 → 明确分工和约定 → 执行 → 确认成果 → 复盘 → 决定是否继续。**

协作开始前，写清各方负责人、交付、时间、费用、成果使用和问题处理方式。推荐伙伴时，说明自己实际了解的能力和合作经历。

### 9.3 网络积累：把成功协作变成可再次使用的连接

一项协作完成后，记录谁能提供什么、在什么条件下适用、谁有过真实合作、怎样发起下一次联系。相关人确认可分享的范围。

新团队开始行动时，可以借用已经允许复用的方法、材料、工具和连接。反复被使用的共同需要出现后，再评估是否增加相应支持。

生态是否在生长，看新行动能否利用已有成果、找到合适伙伴，并培养下一批组织者。

## 10 每周看板：用实际行为判断是否正在变强

每周用同一口径记录，结合人数、具体案例和变化原因判断下一步。小样本时优先写人数和事实。

### 10.1 有效协作：按得到确认的帮助记录

优先观察**每周由成员自主完成的有效协作数**，同时检查成果作用、信任、接续能力和维护负担。

一项有效协作至少有两名参与者，围绕具体需要发生，其中一方确认获得真实帮助，并能说明得到什么。可以是经验、支持、资源连接、共同体验或项目成果。浏览、点赞和寒暄另作参与信息记录。

围绕同一需要形成一次结果确认，记一次；同一项目只有形成可独立确认的阶段成果，才分次记录。一个成果被多人使用时分别记录受益情况，避免把每条消息或每位受益者都加成一次协作。长周期行动记录推进情况，得到结果确认后再计入。

“自主”指成员自行提出需要、联系伙伴并推进，日常过程无需运营者逐项撮合或催办；必要的权限审核和支持不影响这项判断。先由运营者撮合、再由成员完成的协作同样有价值，单独标明撮合来源。

### 10.2 观察口径：分清首次受益、重复合作和接续能力

固定统计窗口，说明分母包含谁。完整观察期尚未结束的人单独列出；分母为零时记录“暂无样本”。

| 观察项             | 怎样记录                                                               | 出现问题先检查什么                                     |
| ------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| 完整行动成果       | 需要确认、执行、成果确认和复盘均完成的行动，以及留下的实际成果         | 需要是否真实、任务是否过大、成果作用是否清楚           |
| 有效协作与自主比例 | 本周有效协作总数、自主完成数；自主完成数 ÷ 有效协作总数                | 帮助是否真实、匹配是否准确、是否仍需逐项催办           |
| 首周获益           | 同批加入且已观察满七天的新人中，首七天至少获得一次确认收获的人数与占比 | 是否有合适机会、联系人是否响应、收获是否被确认         |
| 重复协作           | 同一二十八天窗口内，参与至少两项有效协作的人数 ÷ 参与过有效协作的人数  | 需要是否持续、首次体验如何、下一轮是否合适             |
| 再次参与           | 已完成首次行动且已有下一轮参与机会的人中，实际再次参与的人数与比例     | 参与成本、下一轮安排与暂停原因                         |
| 接续能力           | 新的组织者带完的行动、所需支持和各人的负担                             | 是否真正交接、责任是否清楚、是否压到另一个人身上       |
| 信任与承诺反馈     | 实际受益、兑现约定、问题处理及暂停或离开的具体反馈                     | 是否存在未处理问题、支持范围是否讲清、规则是否一致执行 |
| 维护负担           | 维护者耗时、实际费用、下一轮承诺所需资源                               | 范围是否过宽、重复工作是否整理、资源是否落实           |

首周、二十八天与每周是参考统计窗口，选定后保持口径一致。频率较低的行动按正常周期观察，保留人数和具体事实。

### 10.3 复盘调整：每轮解决最影响结果的一两件事

每周补看两类反馈：参与者是否愿意继续、是否感到承诺得到履行；暂停或离开的人实际因为什么改变了安排。资料阅读者可以反馈用了什么、解决了什么，按实际受益判断其参与价值。

每周写一句判断：

> 本周【哪一环】有了【具体变化】，依据是【事实】；下周由【谁】改进【一件事】，在【时间】检查【结果】。

每轮优先改一到两件最影响结果的事。协作数增加时检查具体作用，确认受益广度、长期积累和质量也在改善。

常见情况的处理：

| 情况                   | 本轮先做什么                             |
| ---------------------- | ---------------------------------------- |
| 赞同的人多，实际参与少 | 回访具体需要，缩小首次行动，重新确认投入 |
| 交流频繁，成果很少     | 选一个真实需要，明确交付、确认人和期限   |
| 发起人包办所有事情     | 列出重复工作，交接一个完整的小任务       |
| 贡献者觉得付出没有回应 | 核对贡献、兑现约定，调整支持与承诺的范围 |
| 新人加入后无事可做     | 放慢接入，补联系人、任务和第一次反馈     |
| 扩大后质量下降         | 缩小规模，修复带教、交接或资源缺口       |
| 成果主要靠内部自我认可 | 请实际使用者提供反馈，核对解决了什么问题 |

## 11 用于生道与生制：把运营安排对齐现行正文

用于本项目时，先明确当前行动由谁、以什么身份承担。共同需要和具体组织的经营目标，都应服务于生道的生生不息。接受帮助、提供帮助和组织行动是参与方式，其变化不自动改变正式身份、职务或治理权限。

| 事项       | 落实要求                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 共同方向   | 以生道为共同目标，以生者正义、大者胜利判断取舍；区分生道与某个具体组织的存续                                                                   |
| 参与身份   | 行生者、组员、股东、职务、学员、候选门人、生生分别确认；参加活动或接受带教不自动转换身份                                                       |
| 生门与生组 | 生门维护和发展生制，践行生道；生组在宪章框架下开展具体行动。生门本身不对外经营                                                                 |
| 教育与实践 | 生校须生门授权，核心目的是为生门输送候选门人；普通培训和活动按实际性质说明，实践机会通常由生组提供                                             |
| 决策与授权 | 运营分工、职务和资源安排须符合现行正文与宪章。三人为表决基础；不足三人时，依赖该基础的规则不适用。组织法为草稿，不把草稿独有规则写成已确认制度 |
| 贡献与分配 | 产出按产权比例分配，产权按功劳变化；常规价值与结构价值按正文区分。贡献记录供核对事实，具体分配按适用规则办理                                   |
| 资源与信息 | 先分清公共资产、组织资产和个人资产。必要公示与其他信息的开放分别处理，记录的查阅、分享和复用范围具体确认                                       |
| 协作网络   | 创办生组与获得生门背书分别办理，进入生门协作网络须符合正文要求；机会与支持以资格和实际资源为前提                                               |

落地时可从一项真实行动开始：明确目标与身份，组织实践，确认成果，记录贡献，积累方法和可信伙伴，再根据结果培养接续者、连接更多合适的生组。

## 12 执行模板：把关键安排写成可直接使用的记录

执行时可先勾选下面六项，再使用对应记录卡：

- [ ] 需要已核对，参与者之间有合适的帮助或协作可能。

- [ ] 已出现受益者确认的收获，并核对是否愿意继续。
